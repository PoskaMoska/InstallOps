# Installation Tracking & Analytics System (InstallOps)

Автоматизированная система сбора данных о монтажах, отслеживания переносов (по расписанию и исполнителям), объективного рейтингования монтажников и синхронизации с Telegram и Google Sheets.

## Технологический стек
* **Язык**: Python 3.12+
* **Фреймворк**: FastAPI (REST API, Webhooks)
* **База данных**: PostgreSQL 16 (с JSONB)
* **ORM**: SQLAlchemy 2.0 (asyncio, Mapped)
* **Миграции**: Alembic
* **Планировщик задач**: APScheduler (in-memory)
* **Интеграции**: Google Sheets API, aiogram (Telegram Bot)
* **Инфраструктура**: Docker, Docker Compose, Nginx

## Подготовка к запуску

1. Склонируйте репозиторий.
2. Создайте файл конфигурации `.env` (используя шаблон):
   ```bash
   cp .env.example .env
   ```
3. Заполните необходимые переменные в `.env`:
   * Данные для подключения к вашей CRM (если используется API, а не Webhooks).
   * `TELEGRAM_BOT_TOKEN` и `TELEGRAM_ADMIN_CHAT_ID`.
   * `GOOGLE_SPREADSHEET_ID` и путь к `credentials.json` (положите сам файл в корень проекта и пропишите `GOOGLE_SERVICE_ACCOUNT_FILE=credentials.json`).

## Запуск (Docker)

Для управления проектом используется `Makefile`:

```bash
# 1. Запустить все сервисы в фоне (Postgres, API, Nginx)
make up

# 2. Применить миграции базы данных (ОБЯЗАТЕЛЬНО ПРИ ПЕРВОМ ЗАПУСКЕ)
make migrate

# 3. Посмотреть логи
make logs
```

## Работа с миграциями (Alembic)
Все изменения моделей БД должны фиксироваться через Alembic. Так как проект упакован в Docker, миграции нужно генерировать внутри контейнера.
Для этого просто внесите изменения в `app/models/` и запустите:

```bash
make make-migrations
```
*Внимание*: Скрипт попытается подключиться к БД, поэтому Docker-контейнеры должны быть запущены (`make up`).

## Интеграция с внешней CRM

В системе предусмотрено 2 пути получения данных:
1. **Webhooks** (Предпочтительно): Настройте вашу CRM отправлять POST-запросы на `http://<ВАШ_СЕРВЕР>/api/webhook`. Payload будет автоматически провалидирован, и изменения сохранятся в историю.
2. **Polling**: Вы можете реализовать адаптер в `app/integrations/external/provider.py` и опрашивать CRM по расписанию (через APScheduler).

## Архитектурные особенности (Audit Checklist)
* **Append-only History**: Таблица `installation_history` никогда не обновляется. Любое изменение даты/монтажника вставляется как новая строка. Запрещено удалять записи.
* **Идемпотентность**: `SyncEngine` защищен от дублей вебхуков. Если событие приходит дважды без фактического изменения даты, статуса или сотрудника, оно игнорируется.
* **Справедливый рейтинг**: Аналитика (`AnalyticsEngine`) учитывает минимальный порог монтажей (`MIN_INSTALLATIONS_FOR_RANKING = 10`) для участия в общем рейтинге.
* **Безопасность**: Доступ к Telegram-боту имеют только пользователи с ID, совпадающим с `TELEGRAM_ADMIN_CHAT_ID`. Google Credentials не захардкожены в код.
